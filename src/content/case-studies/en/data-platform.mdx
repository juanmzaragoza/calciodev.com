## Context

Datakimia is a B2B SaaS company that gives each of its clients access to their own operational analytics. As the platform grew, two problems became urgent: multi-tenant data isolation at scale, and a heavily customized Apache Superset fork that was falling further behind the upstream releases.

## The Problem

**1. No scalable multi-tenancy.** Each client required a manually configured report or dashboard. As the client list grew, so did the manual overhead — and there was no enforcement of data boundaries between clients at the row level, creating security risk.

**2. A stuck BI fork.** Datakimia ran a customized fork of Apache Superset with features not available in the upstream release. The fork was three major versions behind (4.1, while upstream was at 6.1), leaving the platform exposed to unpatched security issues and incompatible with newer integrations.

## What We Did

We worked on two tracks in parallel.

**Multi-tenant backend — built from scratch, in production since May 2024:**
- Enterprise single sign-on (SSO) supporting multiple corporate identity providers
- Role-based access control (RBAC) at both application and data layer
- Apache Superset embedded dashboards with per-client isolation using guest tokens and row-level security (RLS) — no client sees another client's data
- AI data agents: natural-language queries over each client's own data, with guardrails to prevent cross-client data access
- PostgreSQL with per-tenant data boundaries; BigQuery for analytical workloads at scale
- Deployed on Google Cloud with Kubernetes

**Superset fork migration — 3 major versions in 30 days:**
- Automated regression testing to catch features silently lost during each upgrade step
- Merged ~4,400 files across three major versions: Superset 4.1 → 5.x → 6.1
- Caught 3 features with no upstream test coverage that would have broken silently in production
- Reached the current upstream release with all custom functionality intact

## Result

Each Datakimia client now has a secure, self-service analytics environment inside the product — without manual configuration per client and without risk of seeing another tenant's data.

The BI platform is current again. Maintenance overhead dropped: new tenants provision isolated dashboards automatically, and the upgrade gap no longer accumulates.
